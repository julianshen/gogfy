使用說明

所有子指令、旗標與整合點。本頁針對 v0.3.0。

安裝

純 Go 單一執行檔。go install 需要 Go 1.22+。

# 最新版本
$ go install github.com/julianshen/gogfy/cmd/gogfy@latest

# 或指定版本
$ go install github.com/julianshen/gogfy/cmd/gogfy@v0.3.0

# 從原始碼建置
$ git clone https://github.com/julianshen/gogfy && cd gogfy
$ go build -o gogfy ./cmd/gogfy

快速開始

# 在目前的 repo 建圖
$ gogfy run .
# → graphify-out/
#     graph.html        瀏覽器打開即可
#     graph.json        完整圖譜(資料的根據)
#     GRAPH_REPORT.md   god nodes、橋接點、意外連結、建議問題
#     wiki/             每個社群一個 Markdown 頁面

# 串接你的 AI 代理(Claude Code、Cursor、Codex,等等)
$ gogfy claude install

# 後續重建是增量的
$ gogfy run . --update

run 指令

主要流水線:detect → extract → resolve → dedup → cluster → analyze → report → export。

$ gogfy run <root> [flags]
--out <dir>輸出目錄(預設 ./graphify-out/)。
--update增量模式:跳過內容雜湊與上次快取相同的檔案。
--cluster-only不重新抽取,只重新分群目前 --out 下的 graph.json。微調社群偵測時很方便。
--directed在 graph.html 上畫箭頭。
--no-viz不產出 graph.html(更快、輸出更小)。
--graphml另外產出 graph.graphml(可用於 Gephi / yEd)。
--cypher另外產出 graph.cypher(Neo4j 的 MERGE 語法)。
--wiki另外產出 wiki/——每個社群一個 Markdown 頁。
--tree另外產出 tree.html——D3 可摺疊的檔案樹。
--follow-symlinks跟著 root 內的 symlink 目錄遞迴(會記錄已解析路徑避免循環)。
--no-dedup不做實體去重(更快;可能殘留重複節點)。
--semantic --backend <name>啟用 LLM 後端的語意抽取。詳見語意一節。
--dry-run搭配 --semantic,印出事前的 token / 成本估算後直接退出,不發出 LLM 呼叫。
--max-cost-usd <N>事前估算若超過這個上限就終止整個 run。
--transcribe-backend <name>啟用音訊/影片轉錄流程(需要 --semantic)。

子指令參考 — 建立 / 探索

gogfy watch <root>

用 fsnotify 監看檔案變動並持續重建。會印出啟動狀態與每次重建耗時。

$ gogfy watch . [--out dir] [--directed]

gogfy clone <git-url>

純 Go 的 git clone,接著自動跑一次流水線。--no-run 只 clone。

$ gogfy clone https://github.com/foo/bar [--dir D] [--branch B] [--out dir] [--no-run]

gogfy validate <graph.json>

檢查 schema——驗證節點/邊的約束、確認沒有 dangling edge、檢查 language-ID 格式。

gogfy report <graph.json>

從現有圖譜在 stdout 印出 GRAPH_REPORT.md。

gogfy path <source> <target>

兩個節點 ID 之間最短連通路徑。

$ gogfy path go:function:/api.go:Handler go:type:/db.go:DB [--graph graph.json]

gogfy diff <old.json> <new.json>

兩個圖譜快照的結構差異——新增/移除的節點與邊、信心度變化。

gogfy manifest <root>

所有原始碼檔案的 mtime + SHA 快照。--diff 會印出與上次快照之間的變更檔案清單。增量流程會用到。

$ gogfy manifest . [--out dir] [--diff] [--follow-symlinks]

gogfy merge-graphs <a.json> <b.json> ...

把多張圖併成一張(每個 repo 一張 → 組織級的圖)。輸出位置以 --out 指定。

gogfy build-merge <prior.json> <next.json>

增量合併並修剪被刪檔案的節點——保留 prior 中沒變動的檔案節點,用 next 取代有變動的檔案節點,丟掉已刪除檔案的節點。

$ gogfy build-merge prior.json next.json [--files list.txt] [--out merged.json]

gogfy benchmark <graph.json>

token 節省量測:代理讀完整原始碼會吃多少 token,改讀圖譜又少多少。

$ gogfy benchmark graph.json [--corpus-words N] [--depth D] [--json]

從現有圖譜產出周邊產物

gogfy wiki <graph.json>

可被代理爬讀的每個社群一個 Markdown 頁、附交叉連結。索引頁在 wiki/README.md。

gogfy site <graph.json>

自帶搜尋的純靜態 HTML 站,適合丟到 GitHub Pages。可透過 --wiki-dir 重用既有的 wiki/。

gogfy tree <graph.json>

D3 可摺疊檔案樹的 HTML 視圖。

gogfy callflow <graph.json>

帶有標籤與 Key Insights 段落的 Mermaid 架構圖。

$ gogfy callflow graph.json [--max-sections N] [--max-nodes M] [--max-edges E] [--project NAME]

gogfy obsidian <graph.json>

Obsidian vault:每個節點一個 Markdown 檔、邊用 [[wikilinks]] 表達、加上社群總覽。

gogfy svg <graph.json>

靜態力導向 SVG(不需要 JS)——可嵌進文件、部落格、任何地方。

$ gogfy svg graph.json [--out path.svg] [--labels] [--width N] [--height N] [--iterations N]

gogfy labels <graph.json>

為每個社群產生或編輯人類可讀的標籤。--force 會覆寫既有的。

gogfy neo4j-push <graph.json>

透過 Bolt 直接把 graph.json 推進 Neo4j——可取代產出 graph.cypher 再執行的兩步流程。

$ gogfy neo4j-push graph.json --uri neo4j://localhost:7687 --user U --password P [--database D]

CI 整合

當圖譜的回歸超過門檻時讓 PR build 失敗。Markdown 摘要會印到 stdout(可以 pipe 給 gh pr comment);超過門檻會以非 0 結束。

$ gogfy ci base.json head.json \
    --max-removed-nodes 0 \
    --max-removed-edges 10 \
    --max-new-ambiguous 5
--max-removed-nodes <N>消失的節點超過 N 個就失敗。
--max-removed-edges <N>消失的邊超過 N 條就失敗。
--max-new-ambiguous <N>新增的 AMBIGUOUS 邊超過 N 條就失敗。

全域圖譜(多 repo)

放在 home 目錄下的共享圖譜倉,可跨 repo 查詢。

$ gogfy global add graphify-out/graph.json --as myrepo
$ gogfy global list
$ gogfy global path <source> <target>        # 跨 repo 連通性
$ gogfy global remove myrepo
$ gogfy global path                            # 顯示倉的路徑

代理平台

支援 19 種代理平台。combo 安裝會一次幫你接上 MCP 伺服器 + 文件片段 + post-commit 鉤子:

$ gogfy <platform> install
$ gogfy <platform> uninstall            # 加 --purge 同時移除片段與鉤子

# 也可以分步
$ gogfy install --platform <platform>         # 只接 MCP 設定
$ gogfy install-instructions --file CLAUDE.md # 只插入文件片段
$ gogfy hook install                          # post-commit + post-checkout 鉤子

可用平台: claude · codex · cursor · vscode · gemini · opencode · kilocode · qwen · kimi · aider · claw · copilot · droid · trae · trae-cn · hermes · kiro · pi · antigravity

Git hooks

會自動重建圖譜的 post-commit + post-checkout 鉤子,以及一個可選的 merge driver——在 git merge 時自動 union graph.json。

$ gogfy hook install [--repo dir] [--gogfy-bin path] [--out dir]
$ gogfy hook uninstall [--repo dir]
$ gogfy hook status [--repo dir]
$ gogfy hook install-merge-driver [--repo dir] [--gogfy-bin path]
$ gogfy hook uninstall-merge-driver [--repo dir]

MCP 伺服器

無狀態、走 stdio 的 MCP 伺服器。combo 安裝器會幫你接好;gogfy serve 用來直接執行,方便測試或自己接入非標準整合。

$ gogfy serve [--graph graphify-out/graph.json] [--report graphify-out/GRAPH_REPORT.md]

MCP 工具一覽

對外提供 10 個工具,代理可以直接呼叫。全部都是唯讀的;不會修改圖譜。

gogfy_god_nodes圖中連線最多的前 N 個實體(結構性的中樞)。
gogfy_explain單一節點的摘要:它是什麼、誰呼叫/使用它、它依賴什麼。
gogfy_query過濾條件式列出節點——可依 kind、檔案、社群、Label 子字串。
gogfy_path兩節點間最短連通路徑。
gogfy_get_neighbors節點的直接鄰居,並依關係分組。
gogfy_graph_stats統計:按 kind/relation 區分的節點/邊數量、社群大小。
gogfy_get_community單一社群的成員與摘要。
gogfy_traverse從節點出發的 BFS/DFS,支援深度與關係過濾。
gogfy_impact反向可達性:當你修改某節點時,會連帶受影響的所有遞移依賴者。
gogfy_repomap依重要性(PageRank)排序、按檔案分組的關鍵符號地圖(可選擇針對你的任務聚焦)。

語意抽取(可選,LLM 後端)

加上 --semantic 後,gogfy 會從文件與圖片裡多抽取出實體與 N 元的 hyperedges。每個後端都是純 Go 的 HTTP client——不依賴任何官方 SDK。

$ gogfy run . --semantic --backend anthropic --dry-run    # 事前估算
$ gogfy run . --semantic --backend anthropic --max-cost-usd 5.00
anthropicANTHROPIC_API_KEY · Claude(預設 Sonnet)
openaiOPENAI_API_KEY
geminiGEMINI_API_KEY
kimiMOONSHOT_API_KEY · Moonshot / Kimi
bedrockAWS_ACCESS_KEY_ID、AWS_SECRET_ACCESS_KEY、AWS_REGION · 透過 AWS Bedrock 呼叫 Claude(純 Go SigV4)
ollama本機 Ollama endpoint(不需要 key)

結果會快取在 <out>/.gographify-cache/semantic/ 之下;搭配 --update 重跑時,只有變動過的輸入會真的呼叫 LLM。

URL ingestion

把一個 URL 當成圖譜來源拉進語料:SSRF 安全的 fetch、readability 風格的 HTML 萃取、OpenGraph metadata、GitHub URL 重寫、arXiv PDF 路由、YouTube oembed。

$ gogfy ingest https://example.com/post [--out dir]
$ gogfy ingest https://youtu.be/<id> --audio        # 用純 Go 拉音訊給 --transcribe 用
$ gogfy add ...                                     # ingest 的別名

支援的語言與格式

28+ 種程式語言、10+ 種文件格式——全部走純 Go tree-sitter,任何抽取器都不需要 Python 或 LLM。

程式碼: go · py · js/jsx/mjs/cjs · ts/tsx · java · c/h · cpp/cc/cxx/hpp · cs · rs · rb · kt/kts · scala/sc · php · lua · zig · jl · sh/bash · hs · ml · r · ex/exs · erl · swift · dart · fortran · svelte

文件 & 資料: md/mdx/markdown · html/htm · rst · txt · docx · xlsx · pdf · pptx · yaml/yml · toml · gdoc/gsheet/gslides

完整的每語言抽取項目對照表:docs/languages.md。

快取管理

增量的 --update 流程與語意結果都放在 <out>/.gographify-cache/ 之下。

$ gogfy cache stats [--out dir]                                        # 大小與項目數
$ gogfy cache clear [--out dir] [--older-than 7d | --all]              # 清理

設定檔與慣例

.graphifyignore在 walk 層直接跳過的 glob 模式(類似 gitignore)。
.graphifyinclude把通常被略過的隱藏檔/路徑列為允許清單。
tsconfig.json(paths)JS/TS 路徑別名(@app/* → src/*)會在下游合併之前先被讀進來解析。
<out>/.gographify-cache/內容雜湊快取(抽取)+ 語意結果快取。刪掉沒關係,會自動重建。
<out>/graph.json資料的根據(帶版本的 schema,有 schema_version 欄位)。
<out>/GRAPH_REPORT.md會印上語料的 HEAD 短 SHA,過期的版本看一眼就知道。

可複現性保證

同一份語料跑兩次,graph.json 逐位元組相同。--update / diff / ci 都依賴這個保證——否則 CI 守門員會被假變更觸發。

兩個機制一起確保這個保證:預設使用 gogfy 自己的可複現 LouvainClusterer(排序的節點迭代、排序的決勝);以及對 dedup 的邊輸出套用 schema.SortEdges。整段流水線跑兩次、確認 byte 級別相同的 e2e 回歸測試守著。
