インストール

Pure-Go の単一バイナリ。go install には Go 1.22+ が必要です。

# 最新リリース
$ go install github.com/julianshen/gogfy/cmd/gogfy@latest

# またはバージョン指定
$ go install github.com/julianshen/gogfy/cmd/gogfy@v0.3.0

# ソースからビルド
$ git clone https://github.com/julianshen/gogfy && cd gogfy
$ go build -o gogfy ./cmd/gogfy

クイックスタート

# 現在のリポジトリでグラフをビルド
$ gogfy run .
# → graphify-out/
#     graph.html        ブラウザで開ける
#     graph.json        完全なグラフ(信頼できる情報源)
#     GRAPH_REPORT.md   god ノード、橋渡し、意外な接続、質問
#     wiki/             コミュニティごとに Markdown

# AI エージェントに接続(Claude Code、Cursor、Codex など)
$ gogfy claude install

# 以降の再ビルドは増分
$ gogfy run . --update

run コマンド

メインパイプライン:detect → extract → resolve → dedup → cluster → analyze → report → export。

$ gogfy run <root> [flags]
--out <dir>出力ディレクトリ(デフォルト ./graphify-out/)。
--update増分:前回のキャッシュと内容ハッシュが一致するファイルはスキップ。
--cluster-only抽出をスキップ、--out 配下の graph.json を再クラスタリング。コミュニティ検出を調整するときに便利。
--directedgraph.html に矢印を描画。
--no-vizgraph.html をスキップ(高速、出力が小さい)。
--graphmlgraph.graphml も出力(Gephi / yEd 向け)。
--cyphergraph.cypher も出力(Neo4j の MERGE 構文)。
--wikiwiki/ も出力 —— コミュニティごとに Markdown。
--treetree.html も出力 —— D3 折りたたみ可能なファイルツリー。
--follow-symlinksルート内の symlink ディレクトリに降下(解決済みパス記録で循環防止)。
--no-dedupエンティティ重複排除をスキップ(高速だが重複ノードが残る場合あり)。
--semantic --backend <name>LLM 駆動の意味抽出を有効化。意味抽出を参照。
--dry-run--semantic と併用で、事前のトークン / コスト見積もりを表示して LLM 呼び出しなしで終了。
--max-cost-usd <N>事前見積もりがこの上限を超えると実行を中止。
--transcribe-backend <name>音声/動画の文字起こしを有効化(--semantic が必要)。

サブコマンド — ビルド / 探索

gogfy watch <root>

fsnotify によるファイル変更検知での継続再ビルド。起動状態と再ビルド時間をログ出力。

$ gogfy watch . [--out dir] [--directed]

gogfy clone <git-url>

Pure-Go の git clone、続けて自動的にパイプラインを実行。--no-run で clone のみ。

$ gogfy clone https://github.com/foo/bar [--dir D] [--branch B] [--out dir] [--no-run]

gogfy validate <graph.json>

スキーマ検証 —— ノード/エッジの不変条件、dangling edge の不存在、language-ID の形式を確認。

gogfy report <graph.json>

既存のグラフから GRAPH_REPORT.md を標準出力に出力。

gogfy path <source> <target>

2 つのノード ID 間の最短連結パス。

$ gogfy path go:function:/api.go:Handler go:type:/db.go:DB [--graph graph.json]

gogfy diff <old.json> <new.json>

2 つのグラフスナップショット間の構造差分 —— 追加・削除されたノード/エッジ、信頼度の変化。

gogfy manifest <root>

全ソースファイルの mtime + SHA スナップショット。--diff は前回からの変更ファイル一覧を出力。増分フローで使用。

$ gogfy manifest . [--out dir] [--diff] [--follow-symlinks]

gogfy merge-graphs <a.json> <b.json> ...

複数のグラフを 1 つに統合(リポジトリごとのグラフ → 組織全体のグラフ)。出力は --out で指定。

gogfy build-merge <prior.json> <next.json>

削除済みファイルのノードを除去しつつ増分マージ —— prior から未変更ファイルのノードを保持し、next のファイルのノードで置換、削除されたファイルのノードは破棄。

$ gogfy build-merge prior.json next.json [--files list.txt] [--out merged.json]

gogfy benchmark <graph.json>

トークン削減量の測定:エージェントが生のコーパスを読む場合と、グラフを読む場合のトークン消費量比較。

$ gogfy benchmark graph.json [--corpus-words N] [--depth D] [--json]

既存グラフからのアーティファクト生成

gogfy wiki <graph.json>

コミュニティごとに 1 ページの Markdown、相互リンク付きで、エージェントが巡回可能。インデックスは wiki/README.md。

gogfy site <graph.json>

検索機能付きの自己完結型静的 HTML サイト。GitHub Pages にも適合。--wiki-dir で既存の wiki/ を再利用。

gogfy tree <graph.json>

D3 折りたたみ可能なファイルツリー HTML ビュー。

gogfy callflow <graph.json>

ラベルと Key Insights セクション付きの Mermaid アーキテクチャ図。

$ gogfy callflow graph.json [--max-sections N] [--max-nodes M] [--max-edges E] [--project NAME]

gogfy obsidian <graph.json>

Obsidian Vault:ノードごとの Markdown、エッジを [[wikilinks]] で表現、コミュニティ概要付き。

gogfy svg <graph.json>

静的 force-directed SVG(JS 不要)—— ドキュメント、ブログ、どこにでも埋め込み可能。

$ gogfy svg graph.json [--out path.svg] [--labels] [--width N] [--height N] [--iterations N]

gogfy labels <graph.json>

コミュニティごとに人間可読なラベルを生成または編集。--force で上書き。

gogfy neo4j-push <graph.json>

起動中の Neo4j に Bolt プロトコルで graph.json を直接送信 —— graph.cypher を書き出す代わり。

$ gogfy neo4j-push graph.json --uri neo4j://localhost:7687 --user U --password P [--database D]

CI 連携

グラフが閾値を超えて退化した時に PR ビルドを失敗させます。Markdown サマリーが標準出力に(gh pr comment にパイプ可)、閾値違反で非ゼロ終了コード。

$ gogfy ci base.json head.json \
    --max-removed-nodes 0 \
    --max-removed-edges 10 \
    --max-new-ambiguous 5
--max-removed-nodes <N>N 個を超えるノードが消えたら失敗。
--max-removed-edges <N>N 本を超えるエッジが消えたら失敗。
--max-new-ambiguous <N>新規 AMBIGUOUS エッジが N 本を超えたら失敗。

グローバルグラフ(マルチリポジトリ)

ホームディレクトリ配下に置かれる、リポジトリごとのグラフ共有ストア。リポジトリ横断で問い合わせ可能。

$ gogfy global add graphify-out/graph.json --as myrepo
$ gogfy global list
$ gogfy global path <source> <target>        # リポジトリ横断の連結性
$ gogfy global remove myrepo
$ gogfy global path                            # ストアパスを表示

エージェントプラットフォーム

19 種のエージェントプラットフォームに対応。コンボインストールは MCP サーバー + ドキュメントスニペット + post-commit フックを一度に配線します:

$ gogfy <platform> install
$ gogfy <platform> uninstall            # --purge でスニペットとフックも除去

# 個別に
$ gogfy install --platform <platform>         # MCP 設定のみ
$ gogfy install-instructions --file CLAUDE.md # ドキュメントスニペットのみ
$ gogfy hook install                          # post-commit + post-checkout フック

Git フック

グラフを自動再ビルドする post-commit + post-checkout フックと、git マージ時に graph.json を自動 union する任意のマージドライバ。

$ gogfy hook install [--repo dir] [--gogfy-bin path] [--out dir]
$ gogfy hook uninstall [--repo dir]
$ gogfy hook status [--repo dir]
$ gogfy hook install-merge-driver [--repo dir] [--gogfy-bin path]
$ gogfy hook uninstall-merge-driver [--repo dir]

MCP サーバー

ステートレスな stdio ベースの MCP サーバー。コンボプラットフォームインストーラがこれを配線します;gogfy serve は手動でのテストや非標準連携のために直接起動するためのものです。

$ gogfy serve [--graph graphify-out/graph.json] [--report graphify-out/GRAPH_REPORT.md]

公開される MCP ツール

エージェントが呼び出せる 10 個のツール。すべて読み取り専用 —— グラフを変更しません。

gogfy_god_nodes接続数が最も多いエンティティの上位 N 件(構造的ハブ)。
gogfy_explainノード単位のサマリー:何であるか、誰が呼ぶ/使うか、何に依存するか。
gogfy_query条件によるノード一覧 —— kind、ファイル、コミュニティ、Label の部分文字列で絞り込み。
gogfy_path2 ノード間の最短連結パス。
gogfy_get_neighborsノードの直接の隣接、関係別に集計。
gogfy_graph_stats統計:kind/relation 別のノード/エッジ数、コミュニティサイズ。
gogfy_get_community単一コミュニティのメンバーとサマリー。
gogfy_traverseノードからの BFS/DFS、深さと関係フィルタ付き。
gogfy_impact逆到達可能性:ノードを変更したときに壊れる推移的な依存元の集合。
gogfy_repomap重要度(PageRank)順に並べ、ファイル単位でグループ化した主要シンボルのマップ(タスクに合わせてフォーカス可能)。

意味抽出(任意、LLM 駆動)

オプトインの --semantic でドキュメントと画像から抽出したエンティティと N 項の ハイパーエッジ でグラフを強化します。各バックエンドは pure-Go の HTTP クライアント —— SDK 依存なし。

$ gogfy run . --semantic --backend anthropic --dry-run    # 事前見積もり
$ gogfy run . --semantic --backend anthropic --max-cost-usd 5.00
anthropicANTHROPIC_API_KEY · Claude(デフォルト Sonnet)
openaiOPENAI_API_KEY
geminiGEMINI_API_KEY
kimiMOONSHOT_API_KEY · Moonshot / Kimi
bedrockAWS_ACCESS_KEY_ID、AWS_SECRET_ACCESS_KEY、AWS_REGION · AWS Bedrock 経由の Claude(pure-Go SigV4)
ollamaローカル Ollama エンドポイント(キー不要)

結果は <out>/.gographify-cache/semantic/ にキャッシュされます。--update での再実行時、変更されたインプットだけが LLM を呼びます。

URL 取り込み

URL をコーパスにグラフソースとして取り込み:SSRF 安全な fetch、readability 風の HTML 抽出、OpenGraph メタデータ、GitHub URL の書き換え、arXiv PDF ルーティング、YouTube oembed。

$ gogfy ingest https://example.com/post [--out dir]
$ gogfy ingest https://youtu.be/<id> --audio        # --transcribe 用の純 Go 音声抽出
$ gogfy add ...                                     # ingest の別名

キャッシュ管理

増分 --update フローと意味抽出結果は <out>/.gographify-cache/ 配下に保存されます。

$ gogfy cache stats [--out dir]                                        # サイズとエントリ数
$ gogfy cache clear [--out dir] [--older-than 7d | --all]              # GC

設定ファイルと規約

.graphifyignorewalk 層でスキップする glob パターン(gitignore 形式)。
.graphifyinclude通常はスキップされる隠しファイル/パスの許可リスト。
tsconfig.json(paths)JS/TS のパスエイリアス(@app/* → src/*)を読み取り、下流のマージ前に解決します。
<out>/.gographify-cache/内容ハッシュキャッシュ(抽出)+ 意味抽出結果キャッシュ。削除しても再構築されます。
<out>/graph.json信頼できる情報源(schema_version フィールド付きのバージョン付きスキーマ)。
<out>/GRAPH_REPORT.mdコーパスの HEAD 短縮 SHA をスタンプ。古いアーティファクトが一目で分かるように。

決定論性の保証

同じコーパスで複数回実行しても graph.json はバイト単位で一致します。--update / diff / ci はこれに依存します —— そうでなければ CI ゲートが誤検知の差分で発火してしまいます。

2 つの仕組みで実現:gogfy 自身の決定論的な LouvainClusterer をデフォルトとして使用(ソートされたノードイテレーション、ソートされたタイブレーク);および dedup のエッジ出力への schema.SortEdges 適用。フィクスチャ上でパイプラインを 2 回実行し、バイト単位の差分があれば失敗する e2e 回帰テストで保証されています。
