What it does

One graph. Every signal your agent needs.

Most agents grep their way through a repo. gogfy extracts the structure once — calls, type hierarchies, package dependencies, doc references — and serves it through a built-in MCP server. Your agent asks the graph "what calls this?" instead of scanning files.

28+ languages

Go, Python, TS/JS, Java, C/C++, C#, Rust, Kotlin, Scala, Swift, Ruby, PHP, Dart, Lua, Haskell, OCaml, Elixir, Erlang, R, Julia, Zig, Fortran, Bash, Svelte, and more — all via pure-Go tree-sitter, no Python or LLM required.

Documents too

Markdown, HTML, PDF, DOCX, PPTX, XLSX, RST, TOML, YAML — treated as first-class graph sources, not comments. Cross-format graphs compose seamlessly.

Typed edges

calls, contains, imports (resolved to corpus modules), inherits, implements, embeds, references, plus N-ary hyperedges from semantic extraction.

How it works

An eight-stage pipeline you can stop at any point.

Each stage is pure-Go, deterministic, and independently testable. No cgo (outside tree-sitter), no Python, no LLM unless you opt in with --semantic.

1Detect
walk, classify, skip secrets
2Extract
tree-sitter AST → nodes
3Resolve
calls, methods, inheritance, imports
4Dedup

Quick start

Three commands, then your agent reads the graph.

# 1. install
$ go install github.com/julianshen/gogfy/cmd/gogfy@latest

# 2. build the graph for the repo you're in
$ gogfy run .
#   graphify-out/
#   ├── graph.html      open in any browser
#   ├── GRAPH_REPORT.md god nodes, surprising connections, suggested questions
#   ├── graph.json      the full graph
#   └── wiki/           one Markdown page per community

# 3. wire it into your AI agent (works with 19 platforms)
$ gogfy claude install
#   installs the MCP server, drops a CLAUDE.md snippet,
#   sets up a post-commit hook that auto-rebuilds.
#   Other targets: cursor, codex, vscode, gemini, aider, ...

Your agent now answers questions about the repo by querying the graph — gogfy_god_nodes, gogfy_traverse, gogfy_path, gogfy_get_neighbors, gogfy_explain — instead of grepping.

Features

Built for real codebases.

Type hierarchy

inherits / implements / embeds resolved across packages for Python, Java, TS, C#, Kotlin, Scala, Swift, Dart, Ruby, PHP, Rust, Go (struct embedding).

Cross-package dependencies

Local imports resolve to the modules they actually name — real cross-file dependency edges instead of dead-end import stubs. External imports stay as observed-path facts.

Deterministic by default

graph.json is byte-identical across runs on the same corpus. Guarded by an e2e regression test. Required for --update / graphdiff and snapshot stability.

MCP server built in

gogfy serve exposes the graph as MCP tools. 19 supported agent platforms — Claude Code, Cursor, Codex, Gemini CLI, Copilot CLI, Aider, and more — can read it without bespoke glue.

Optional semantic enrichment

Opt into LLM extraction with --semantic: entities and N-ary hyperedges over your docs and images. Backends: Anthropic, OpenAI, Gemini, Bedrock, Kimi, Ollama. Pre-flight cost estimation + --dry-run + budget cap.

Incremental & cached

--update rebuilds only changed files via content-hash cache. Semantic results cached at .gographify-cache/. --watch for continuous rebuild.

Multiple export formats

JSON (versioned schema), interactive HTML, Markdown report, GraphML for Gephi/yEd, Cypher for Neo4j (or direct Bolt push), SVG, deployable static doc-site (gogfy site).

Ingest beyond the filesystem

URL ingest with SSRF-safe fetch, readability-style HTML narrowing, OpenGraph metadata, GitHub URL rewrites, arXiv PDF routing, YouTube oembed + pure-Go audio extraction for transcription.

Hardening built in

Sensitive-file patterns at the walk layer, central Label/SourceFile sanitization, SSRF guards, panic-tolerant PDF/OOXML readers. Failures degrade with diagnostics, not silence.

Performance

~4× faster end-to-end in v0.3.0.

Measured on a real 220-file Go corpus (3,885 nodes, 14,869 edges). Profiling found the costs weren't where intuition put them — the wins came from int-indexed parallel Brandes and from hoisting loop invariants out of dedup's O(n²) fuzzy scan.
