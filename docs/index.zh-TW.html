給 AI 代理
使用的程式碼知識圖譜。

一個純 Go 寫成的靜態分析工具。把你的程式碼,連同文件、PDF、網頁、YouTube 影片, 全部變成一張帶型別的知識圖。函式呼叫、型別、繼承關係、import、相依、語意概念——所有訊號集中在同一個結構裡, 讓你的編碼代理在回答關於專案的問題之前,先讀懂這張圖。

前往 GitHub 版本發布 使用說明
$ go install github.com/julianshen/gogfy/cmd/gogfy@latest
功能

一張圖,所有你的代理需要的訊號。

大多數代理在程式碼裡靠 grep 找東西。gogfy 一次把結構抽出來——函式呼叫、型別階層、套件相依、文件參照——再透過內建的 MCP 伺服器提供。 你的代理會「問」圖譜「哪些地方呼叫了這個?」,而不是去掃檔案。

28+ 種程式語言

Go、Python、TS/JS、Java、C/C++、C#、Rust、Kotlin、Scala、Swift、Ruby、PHP、Dart、Lua、Haskell、OCaml、Elixir、Erlang、R、Julia、Zig、Fortran、Bash、Svelte 等等——全部走純 Go tree-sitter,不需要 Python、不需要 LLM。

文件也算數

Markdown、HTML、PDF、DOCX、PPTX、XLSX、RST、TOML、YAML——當成第一級的圖譜來源,而不是註解。跨格式的圖可以無縫合併。

帶型別的邊

calls、contains、imports(會解析到專案內的模組)、inherits、implements、embeds、references,再加上語意抽取產出的 N 元 hyperedges。

運作方式

八階段流水線,任何一階段都可以單獨停在那裡。

每個階段都是純 Go、可複現、可獨立測試的。 除了 tree-sitter 以外不需要 cgo,不需要 Python,除非你加上 --semantic 才會用到 LLM。

1Detect
遍歷、分類、跳過機密
2Extract
tree-sitter AST → 節點
3Resolve
calls、methods、繼承、imports
4Dedup
精確 + 模糊 + LLM 仲裁
5Cluster
可複現的 Louvain
6Analyze
god nodes、意外連結、橋接點
7Report
GRAPH_REPORT.md
8Export
JSON / HTML / GraphML / Cypher / SVG
快速開始

三個指令,你的代理就能讀圖了。

# 1. 安裝
$ go install github.com/julianshen/gogfy/cmd/gogfy@latest

# 2. 對目前的專案建圖
$ gogfy run .
#   graphify-out/
#   ├── graph.html       任意瀏覽器都能打開
#   ├── GRAPH_REPORT.md  god nodes、意外連結、建議問題
#   └── graph.json       完整圖譜

# 3. 串接你的 AI 代理(支援 19 種平台)
$ gogfy claude install
#   安裝 MCP 伺服器、寫入 CLAUDE.md 片段、
#   設定 post-commit 鉤子自動重建。
#   其他目標:cursor、codex、vscode、gemini、aider、……

從現在起,你的代理會透過呼叫圖譜——gogfy_god_nodes、gogfy_traverse、gogfy_path、gogfy_get_neighbors、gogfy_explain——來回答關於專案的問題,不再 grep 檔案。

特色

為真實的程式碼庫而生。

型別階層

跨套件解析 inherits / implements / embeds 邊,支援 Python、Java、TS、C#、Kotlin、Scala、Swift、Dart、Ruby、PHP、Rust、Go(struct 嵌入)。

跨套件相依

本地 import 會被解析到實際引用的模組——產出真實的跨檔案相依邊,而不是停在 import stub。外部 import 仍保留為「看到這個 import」的觀察事實。

預設可複現

同一份程式碼跑兩次,graph.json 逐位元組相同。有端對端回歸測試守著。--update / graphdiff / 快照穩定性都依賴這個保證。

內建 MCP 伺服器

gogfy serve 把圖譜以 MCP 工具的形式對外提供。19 種代理平台——Claude Code、Cursor、Codex、Gemini CLI、Copilot CLI、Aider……——不需要自己寫 glue 就可以讀取。

可選的語意增強

加上 --semantic 啟用 LLM 抽取:從文件與圖片中產出實體與 N 元 hyperedges。後端:Anthropic、OpenAI、Gemini、Bedrock、Kimi、Ollama。提供事前的成本估算、--dry-run 與預算上限。

增量 & 快取

--update 透過內容雜湊快取,只重建有變更的檔案。語意結果快取在 .gographify-cache/ 之下。--watch 可做持續重建。

多種輸出格式

JSON(帶版本的 schema)、互動式 HTML、Markdown 報告、給 Gephi/yEd 的 GraphML、給 Neo4j 的 Cypher(或直接以 Bolt 推送)、SVG、可部署的靜態文件站(gogfy site)。

不只是檔案系統

URL ingest,搭配 SSRF 安全的 fetch、readability 風格的 HTML 萃取、OpenGraph metadata、GitHub URL 重寫、arXiv PDF 路由、YouTube oembed + 純 Go 的影片音訊抽取(供 transcribe 流程)。

強化內建

在 walk 層偵測機密檔名、AddNode 入口統一清洗 Label/SourceFile、SSRF 防護、PDF/OOXML 讀取的 panic-tolerant 保護。失敗會降級並回報,不會無聲消失。

效能

v0.3.0 端對端快了約 4 倍。

在真實的 220 個 Go 檔案語料(3,885 個節點、14,869 條邊)上測得。 Profiling 發現成本不在直覺上的位置——大幅提升來自於 int 索引化加上並行的 Brandes 演算法,以及把 dedup 的 O(n²) 模糊掃描中的不變量提到迴圈外。

~5 秒完整執行時間
215×betweenness 加速
1227測試通過
0執行時非決定性
