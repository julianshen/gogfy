Usage reference

Every subcommand, flag, and integration point. Generated from v0.3.0.

Install

Pure-Go single binary. Requires Go 1.22+ for go install.

# latest release
$ go install github.com/julianshen/gogfy/cmd/gogfy@latest

# or pin a version
$ go install github.com/julianshen/gogfy/cmd/gogfy@v0.3.0

# build from source
$ git clone https://github.com/julianshen/gogfy && cd gogfy
$ go build -o gogfy ./cmd/gogfy

Quick start

# build the graph for the repo you're in
$ gogfy run .
# → graphify-out/
#     graph.html        open in any browser
#     graph.json        the full graph (the source of truth)
#     GRAPH_REPORT.md   god nodes, bridges, surprising connections, questions
#     wiki/             one Markdown page per community

# wire it into your AI agent (Claude Code, Cursor, Codex, etc.)
$ gogfy claude install

# subsequent rebuilds are incremental
$ gogfy run . --update

The run command

The main pipeline: detect → extract → resolve → dedup → cluster → analyze → report → export.

$ gogfy run <root> [flags]
--out <dir>Output directory (default ./graphify-out/).
--updateIncremental: skip files whose content-hash matches the cache from a prior run.
--cluster-onlySkip extraction; re-cluster the existing graph.json under --out. Useful when iterating on community detection.
--directedRender arrowheads on graph.html.
--no-vizSkip the graph.html visualization (faster, smaller output).
--graphmlAlso emit graph.graphml for Gephi / yEd.
--cypherAlso emit graph.cypher (MERGE DDL for Neo4j).
--wikiAlso emit wiki/ — one Markdown page per community.
--treeAlso emit tree.html — D3 collapsible filesystem tree.
--follow-symlinksDescend into in-root symlinked directories (cycle-safe via resolved-path bookkeeping).
--no-dedupSkip entity deduplication (faster; may leave duplicate nodes).
--semantic --backend <name>Opt into LLM-backed semantic extraction. See Semantic.
--dry-runWith --semantic, print the pre-flight token/cost estimate and exit without making LLM calls.
--max-cost-usd <N>Abort the run if the semantic pre-flight estimate exceeds this cap.
--transcribe-backend <name>Enable audio/video transcription pipeline (requires --semantic).

Subcommand reference — build / explore

gogfy watch <root>

Continuous rebuild on file changes (fsnotify-driven). Logs startup state + rebuild duration.

$ gogfy watch . [--out dir] [--directed]

gogfy clone <git-url>

Pure-Go git clone, then auto-run the pipeline. --no-run just clones.

$ gogfy clone https://github.com/foo/bar [--dir D] [--branch B] [--out dir] [--no-run]

gogfy validate <graph.json>

Schema check — verifies node/edge invariants, dangling-edge absence, language-ID format.

gogfy report <graph.json>

Render GRAPH_REPORT.md to stdout from an existing graph.

gogfy path <source> <target>

Shortest connectivity path between two node IDs.

$ gogfy path go:function:/api.go:Handler go:type:/db.go:DB [--graph graph.json]

gogfy diff <old.json> <new.json>

Structural diff between two graph snapshots — added/removed nodes & edges, confidence shifts.

gogfy manifest <root>

mtime + SHA snapshot of all source files. --diff prints the changed-file list against the prior snapshot. Used by incremental flows.

$ gogfy manifest . [--out dir] [--diff] [--follow-symlinks]

gogfy merge-graphs <a.json> <b.json> ...

Union multiple graphs into one (per-repo graphs → org-level graph). Output via --out.

gogfy build-merge <prior.json> <next.json>

Incremental merge with deleted-file prune — keeps untouched-file nodes from prior, replaces nodes from next's files, drops nodes for deleted files.

$ gogfy build-merge prior.json next.json [--files list.txt] [--out merged.json]

gogfy benchmark <graph.json>

Token-reduction measurement: how many tokens an agent would consume reading the raw corpus vs the graph.

$ gogfy benchmark graph.json [--corpus-words N] [--depth D] [--json]

Artifacts from an existing graph

gogfy wiki <graph.json>

Agent-crawlable per-community Markdown pages with cross-links. Index page at wiki/README.md.

gogfy site <graph.json>

Self-contained static HTML site with search, suitable for GitHub Pages. Reuses an existing wiki/ directory via --wiki-dir.

gogfy tree <graph.json>

D3 collapsible filesystem-tree HTML view.

gogfy callflow <graph.json>

Mermaid architecture diagram with labels and a Key Insights section.

$ gogfy callflow graph.json [--max-sections N] [--max-nodes M] [--max-edges E] [--project NAME]

gogfy obsidian <graph.json>

Obsidian vault: one Markdown file per node, [[wikilinks]] for edges, community overviews.

gogfy svg <graph.json>

Static force-directed SVG (no JS) — embed in docs, blog posts, anywhere.

$ gogfy svg graph.json [--out path.svg] [--labels] [--width N] [--height N] [--iterations N]

gogfy labels <graph.json>

Generate or edit human-readable labels per community. --force overwrites.

gogfy neo4j-push <graph.json>

Direct push of graph.json to a running Neo4j via Bolt protocol — alternative to writing graph.cypher.

$ gogfy neo4j-push graph.json --uri neo4j://localhost:7687 --user U --password P [--database D]

CI integration

Fail a PR build when the graph regresses past thresholds. Markdown summary on stdout (pipe to gh pr comment); non-zero exit code on breach.

$ gogfy ci base.json head.json \
    --max-removed-nodes 0 \
    --max-removed-edges 10 \
    --max-new-ambiguous 5
--max-removed-nodes <N>Fail if more than N nodes vanished.
--max-removed-edges <N>Fail if more than N edges vanished.
--max-new-ambiguous <N>Fail if more than N new AMBIGUOUS edges appeared.

Global graph (multi-repo)

A shared store of per-repo graphs you can query across, on top of your home directory.

$ gogfy global add graphify-out/graph.json --as myrepo
$ gogfy global list
$ gogfy global path <source> <target>        # cross-repo connectivity
$ gogfy global remove myrepo
$ gogfy global path                            # show store path

Agent platforms

19 agent platforms supported. The combo install wires the MCP server + a docs snippet + a post-commit hook in one shot:

$ gogfy <platform> install
$ gogfy <platform> uninstall            # add --purge to remove snippet + hook too

# or step-by-step
$ gogfy install --platform <platform>         # just the MCP config
$ gogfy install-instructions --file CLAUDE.md # just the docs snippet
$ gogfy hook install                          # post-commit + post-checkout hooks

Git hooks

Post-commit + post-checkout hooks that auto-rebuild the graph, and an optional merge driver that auto-unions graph.json during git merges.

$ gogfy hook install [--repo dir] [--gogfy-bin path] [--out dir]
$ gogfy hook uninstall [--repo dir]
$ gogfy hook status [--repo dir]
$ gogfy hook install-merge-driver [--repo dir] [--gogfy-bin path]
$ gogfy hook uninstall-merge-driver [--repo dir]

MCP server

Stateless stdio-based MCP server. The combo platform installer wires this for you; gogfy serve runs it directly for testing or non-installer integrations.

$ gogfy serve [--graph graphify-out/graph.json] [--report graphify-out/GRAPH_REPORT.md]

MCP tools exposed

Ten tools your agent can call. All read-only; none modify the graph.

gogfy_god_nodesTop-N most-connected entities (the structural hubs).
gogfy_explainPer-node summary: what it is, who calls/uses it, what it depends on.
gogfy_queryFiltered listing — by kind, file, community, label substring.
gogfy_pathShortest connectivity path between two nodes.
gogfy_get_neighborsDirect neighbors of a node with relation breakdown.
gogfy_graph_statsCounts: nodes/edges by kind/relation; community sizes.
gogfy_get_communityMembers + summary of a single community.
gogfy_traverseBFS/DFS from a node with depth + relation filters.
gogfy_impactReverse-reachability: the transitive dependents that break if you change a node.
gogfy_repomapRanked, file-grouped map of the most important symbols (PageRank; optionally focused on your task).

Semantic extraction (LLM-backed, optional)

Opt-in --semantic enriches the graph with entities and N-ary hyperedges extracted from documents and images. Pure-Go HTTP clients for each backend — no SDK dependency.

$ gogfy run . --semantic --backend anthropic --dry-run    # pre-flight estimate
$ gogfy run . --semantic --backend anthropic --max-cost-usd 5.00
anthropicANTHROPIC_API_KEY · Claude (default Sonnet)
openaiOPENAI_API_KEY
geminiGEMINI_API_KEY
kimiMOONSHOT_API_KEY · Moonshot / Kimi
bedrockAWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AWS_REGION · Claude via AWS Bedrock (pure-Go SigV4)
ollamaLocal Ollama endpoint (no key)

Results are cached at <out>/.gographify-cache/semantic/; rerunning --update only hits the LLM for changed inputs.

URL ingestion

Pull a URL into the corpus as a graph source: SSRF-safe fetch, readability-style HTML narrowing, OpenGraph metadata, GitHub URL rewrites, arXiv PDF routing, YouTube oembed.

$ gogfy ingest https://example.com/post [--out dir]
$ gogfy ingest https://youtu.be/<id> --audio        # pure-Go audio extraction for --transcribe
$ gogfy add ...                                     # alias for ingest

Cache management

The incremental --update flow and semantic results live under <out>/.gographify-cache/.

$ gogfy cache stats [--out dir]                                        # size + entry counts
$ gogfy cache clear [--out dir] [--older-than 7d | --all]              # GC

Config files & conventions

.graphifyignoreGlob patterns to skip at the walk layer (gitignore-style).
.graphifyincludeAllowlist for hidden files / paths normally skipped.
tsconfig.json (paths)JS/TS path aliases (@app/* → src/*) are read and resolved before downstream merge.
<out>/.gographify-cache/Content-hash cache (extraction) + semantic-result cache. Safe to delete; will rebuild.
<out>/graph.jsonSource of truth (versioned schema with schema_version field).
<out>/GRAPH_REPORT.mdStamped with the corpus's HEAD short SHA so a stale artifact is visibly out-of-date.

Determinism guarantee

graph.json is byte-identical across repeated runs on the same corpus. This is load-bearing for --update / diff / ci — spurious diffs would break the CI gate.

Two pieces enforce it: gogfy's own deterministic LouvainClusterer as the default (sorted iteration, sorted tie-breaks) and schema.SortEdges applied to dedup's edge output. Guarded by an end-to-end regression test that runs the pipeline twice on a fixture and fails on any byte-level difference.
